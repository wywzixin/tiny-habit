# Tiny Habits - 产品需求文档 (PRD)

## 1. 产品概述

### 1.1 产品名称
**Tiny Habits（微习惯）**

### 1.2 产品定位
基于福格行为模型（Fogg Behavior Model）的习惯养成应用，通过科学的行为设计方法帮助用户建立持久的好习惯。

### 1.3 目标用户
**主要用户**：25-40岁都市白领
- 希望改善生活习惯但屡次失败
- 工作繁忙，时间碎片化
- 追求自我提升和生活品质

**用户痛点**：
- 目标太大，难以坚持
- 缺乏即时反馈
- 不知如何开始

**解决方案**：
- 微行为：30秒内完成
- 即时庆祝：动画+积分
- 锚点提示：连接现有习惯

### 1.4 核心价值主张
> "每一个微小的开始，都通向伟大的改变"

通过将大目标拆解为极小的微行为，绑定到日常已有的锚点行为上，配合即时庆祝反馈，让习惯养成变得简单可持续。

### 1.5 双模式数据存储设计

**设计理念**：支持未登录用户完整体验，登录后无缝切换到云端存储。

#### 未登录模式（Guest Mode）🔓

**数据存储**：AsyncStorage（本地）

**功能特性**：
- ✅ 完整的习惯养成功能
- ✅ 创建配方、打卡、查看统计
- ✅ 查看系统预设习惯库（本地代码）
- ✅ 完全离线可用，无需网络
- ❌ 无云同步，无多设备支持
- ❌ 数据仅存本地，卸载应用后丢失

**数据来源**：
```
用户习惯：AsyncStorage（用户创建的习惯）
系统习惯：本地代码预置（10个系统习惯）
微行为：AsyncStorage
打卡记录：AsyncStorage
```

#### 已登录模式（Authenticated Mode）🔐

**数据存储**：Java 后端 + MySQL

**功能特性**：
- ✅ 所有功能完整支持
- ✅ 云端存储，数据永久保存
- ✅ 多设备同步
- ✅ 数据备份与恢复
- ✅ 查看系统习惯库（后端 API）
- ✅ 未来支持社交分享

**数据来源**：
```
用户习惯：后端 API
系统习惯：后端 API
微行为：后端 API
打卡记录：后端 API
```

#### 登录时数据迁移

**迁移流程**：
```
1. 用户登录成功
2. 读取 AsyncStorage 中的所有数据
3. 上传到后端数据库
4. 上传成功后清空 AsyncStorage
5. 切换到云端数据源
```

**迁移内容**：
- 用户创建的习惯
- 所有微行为配方
- 历史打卡记录
- 行动值积分

**设计优势**：
- 🎯 **降低门槛**：无需注册即可体验完整功能
- 🚀 **性能优秀**：未登录用户无网络请求，速度快
- 🔄 **无缝切换**：登录后自动迁移数据
- 💾 **数据安全**：登录后数据永久保存

## 2. 福格行为模型

### 2.1 模型公式
```
B = MAP
行为(Behavior) = 动机(Motivation) × 能力(Ability) × 提示(Prompt)
```

### 2.2 模型在产品中的应用

| 模型要素 | 产品功能 | 设计目标 |
|---------|---------|---------|
| **Motivation（动机）** | 行动值积分、庆祝动画、成就系统、鼓励文案 | 提供持续的正向激励 |
| **Ability（能力）** | 微行为设计（极小化任务）、难度分级 | 降低行动门槛 |
| **Prompt（提示）** | 锚点系统、智能提醒、通知推送 | 在正确时机触发行为 |

### 2.3 配方公式
```
当 [锚点行为] 后，我会 [微行为]，然后 [庆祝方式]
```

示例：
- 当 **刷完牙** 后，我会 **用牙线清洁一颗牙**，然后 **对自己微笑**
- 当 **倒好咖啡** 后，我会 **做两次深呼吸**，然后 **心里说太棒了**

### 3.2 首页 (Home)

**功能描述：** 用户的微行为管理中心，展示所有已创建的微行为配方，支持快速打卡。

**数据说明：** 首页展示的是微行为（子级），每个微行为归属于一个父习惯。

| 功能点 | 描述 | 优先级 |
|-------|------|-------|
| 微行为列表 | 展示用户所有微行为，显示锚点和行为 | P0 |
| 打卡按钮 | 点击完成微行为打卡，触发庆祝反馈 | P0 |
| 行动值显示 | 顶部显示累计行动值 | P0 |
| 今日能量卡片 | 展示每日激励语，点击触发彩带动画 | P1 |
| 完成状态 | 已完成微行为显示划线样式 | P0 |
| 父习惯分组 | 可按父习惯分组显示微行为 | P1 |

**交互细节：**
- 打卡时触发触觉反馈（震动）
- 打卡后显示烟花动画 + 庆祝弹窗
- 庆祝弹窗显示对应的庆祝方式提醒
- 弹窗 3 秒后自动关闭

### 3.3 发现页 (Discover) - 配方库

**功能描述：** 微行为配方模板库，提供系统预设的完整配方，用户可直接添加为打卡项。

**核心逻辑：**
- 配方库展示的是**微行为模板**（behavior_recipe_template 表）
- 用户点击"+"直接添加微行为到自己的打卡列表
- 添加的微行为**不绑定习惯**（habitId = null）
- 用户可以在首页直接打卡，无需先创建习惯

**数据来源：**
- 系统预设配方（官方精选）

| 功能点 | 描述 | 优先级 |
|-------|------|-------|
| 配方列表 | 展示所有微行为配方模板，卡片形式 | P0 |
| 分类筛选 | 推荐/健康/学习/生活/心理/社交 | P0 |
| 搜索功能 | 关键词搜索配方名称和描述 | P1 |
| 配方预览 | 显示完整配方：锚点→行为→庆祝 | P0 |
| 一键添加 | 点击"+"直接添加为我的打卡配方 | P0 |
| 热度排序 | 按使用人数排序 | P1 |

**配方卡片信息：**
- 配方图标和名称
- 完整配方预览（锚点→行为→庆祝）
- 分类标签
- 难度标签（简单/适中/挑战）
- 使用人数

**交互流程：**
```
浏览配方库 → 点击配方卡片的"+" → 直接添加到我的微行为 → 完成
```

**接口调用：**
```javascript
// 1. 获取配方模板列表
GET /api/library/recipes?category=健康

// 2. 点击"+"添加配方
POST /api/micro-behavior/add-from-template
{
  "templateId": 1,
  "frequency": "[1,2,3,4,5,6,7]",
  "reminderEnabled": false
}

// 3. 添加成功后，微行为出现在首页
// habitId = null（不绑定习惯）
```

**设计要点：**
- ✅ 快速添加：一键添加，无需选择习惯
- ✅ 灵活打卡：添加后直接在首页打卡
- ✅ 后续整理：用户可以后续将微行为归类到习惯下

### 3.4 创建配方页 (Create)

**功能描述：** 核心页面，引导用户按福格模型创建微行为配方。

**核心逻辑：**
- 用户可以选择或创建一个**父习惯**
- 在该习惯下创建**微行为**（子级）
- 习惯和微行为通过一个接口同时创建

**数据层级：**
```
习惯（父级）── 通过习惯库选择或手动创建
  └── 微行为（子级）：锚点 + 行为 + 庆祝
```

**创建流程：**
```
选择/创建习惯 → 输入微行为目标 → AI推荐微行为 → 选择锚点 → 庆祝方式 → 频率设置 → 确认
```

| 功能点 | 描述 | 优先级 |
|-------|------|-------|
| 习惯输入框 | 输入或选择父习惯名称 | P0 |
| 习惯库按钮 | 输入框右侧按钮，点击弹出习惯库 | P0 |
| 目标输入 | 输入微行为目标 | P0 |
| AI推荐微行为 | 推荐4个微行为选项 | P0 |
| 难度标签 | 简单/适中/挑战 | P1 |
| AI推荐锚点 | 推荐4个触发时机 | P0 |
| 庆祝方式 | 6种预设庆祝方式 | P0 |
| 频率设置 | 周一至周日选择 | P0 |
| 提醒设置 | 选择提醒时间 | P0 |
| 配方预览 | 底部实时预览完整配方 | P0 |

#### 3.4.1 习惯库（弹窗）

**入口：** 创建配方页 → 习惯输入框右侧按钮

**核心逻辑：**
- 习惯库展示**用户自己创建的习惯** + **系统预设习惯**
- 用一个字段区分来源（user/system）
- 用户创建的习惯分类默认为"新建"
- 选择习惯后，只是填充名称到输入框，不会提前创建习惯
- 最终通过"创建配方"接口统一创建习惯+微行为

**习惯库来源：**
- 用户自己创建的习惯（category = "新建"）
- 系统预设习惯（category = 健康/学习/生活等）

| 功能点 | 描述 | 优先级 |
|-------|------|-------|
| 习惯列表 | 展示用户习惯 + 系统习惯 | P0 |
| 分组显示 | 我创建的 / 系统推荐 | P0 |
| 分类筛选 | 推荐/健康/学习/生活/心理/社交 | P0 |
| 搜索功能 | 关键词搜索习惯 | P1 |
| 选择习惯 | 点击选择，自动填充到输入框 | P0 |

**习惯库卡片信息：**
- 习惯图标和名称
- 分类标签（用户创建的显示"新建"）
- 微行为数量（仅用户习惯显示）
- 来源标识（我创建的 / 系统推荐）

**接口调用：**
```javascript
// 1. 打开习惯库弹窗
GET /api/habit/library?category=健康

// 响应数据：
{
  "data": [
    {
      "id": 1,
      "name": "健康生活",
      "icon": "💪",
      "category": "新建",
      "source": "user",           // 用户创建的
      "microBehaviorCount": 3
    },
    {
      "id": 1,
      "name": "多喝水",
      "icon": "💧",
      "category": "健康",
      "source": "system",          // 系统预设的
      "description": "每天8杯水",
      "popularity": 100
    }
  ]
}

// 2. 用户选择习惯后，填充到输入框
// 前端只是把名称、图标、分类填充到输入框

// 3. 用户填写完微行为信息后，提交创建配方
POST /api/recipe/create
{
  "habitId": null,              // 创建新习惯
  "habitName": "多喝水",        // 从习惯库选择的名称
  "habitIcon": "💧",
  "habitCategory": "健康",
  "microBehavior": {
    "name": "晨起喝水",
    "anchor": "起床后",
    "behavior": "喝一口水",
    "celebration": "对自己微笑",
    "difficulty": "easy",
    "frequency": "[1,2,3,4,5,6,7]",
    "reminderEnabled": false
  }
}

// 4. 后端创建习惯 + 微行为
// 习惯和微行为通过一个接口同时创建
```

**设计要点：**
- ✅ 习惯库只是提供名称建议，不会提前创建习惯
- ✅ 用户可以从习惯库选择，也可以手动输入
- ✅ 最终通过"创建配方"接口统一创建
- ✅ 用户创建的习惯分类默认为"新建"

**庆祝方式选项：**
- 对自己微笑
- 心里说"太棒了"
- 握拳庆祝
- 点头认可
- 深呼吸
- 自定义

### 3.5 我的习惯库页面（管理页面）

#### 3.7.1 登录与账号体系 (Auth)

**功能描述：** 提供用户登录、注册、找回密码、第三方登录，以及基础资料维护（头像/昵称/性别）。

**支持的登录方式：**
- **邮箱/手机号 + 密码登录（P0）**
  - 输入支持：邮箱格式或纯数字手机号（≥6 位）
  - 密码支持显示/隐藏切换
- **第三方登录（P1）**
  - **QQ 登录**：iOS/Android
  - **微博登录**：iOS/Android
  - **Apple ID 登录**：仅 iOS（Android 不显示入口）

**注册（P0）：**
- 支持 **邮箱或手机号注册**，设置登录密码后自动登录
- 密码支持显示/隐藏切换

**忘记密码（P0）：**
- 支持通过 **邮箱或手机号** 直接重置密码
- 新密码需二次确认
- 为简化流程，无需验证码验证

**用户资料（P1）：**
- 入口：个人中心头像/昵称区域 → 用户信息页
- 支持编辑：头像（拍照/相册）、昵称、性别（男/女/未知）
- 账号展示：邮箱/手机号（根据用户绑定信息展示）

**不支持（MVP 明确边界）：**
- 不支持短信验证码登录/注册（需要短信通道成本）
- 不支持微信登录（需要企业资质/审核与成本）

### 3.8 奖励系统 (Rewards)

**功能描述：** 用户可以设定个人奖励，用行动值兑换。

**核心流程：**
```
创建奖励 → 积累行动值 → 达标兑换 → 记录历史
```

| 功能点 | 描述 | 优先级 |
|-------|------|-------|
| 创建奖励 | 设置名称、图标、所需行动值 | P1 |
| 奖励列表 | 展示所有待兑换奖励 | P1 |
| 兑换功能 | 扣除行动值，标记已兑换 | P1 |
| 兑换历史 | 查看已兑换的奖励记录 | P2 |

**积分规则：**
- 每次打卡 +10 行动值
- 行动值分为：累计、可用、已兑换
- 兑换后从可用行动值中扣除

**约束规则：**
- 每个用户最多创建 50 个奖励
- 奖励成本最低 10 行动值
- 兑换后不可撤销

## 6. 不做什么（明确边界）

### 6.1 MVP 阶段不做

**社交功能**
- 不做好友系统
- 不做习惯分享
- 不做排行榜
- 理由：专注个人习惯养成

**付费功能**
- 不做会员订阅
- 不做内购
- 理由：MVP 验证产品价值

### 6.2 永远不做

**强制性功能**
- 不强制每天打卡
- 不惩罚断签
- 理由：正向激励
